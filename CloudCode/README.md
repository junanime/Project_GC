분류 우선순위는 보스 → 미니보스 → 엘리트 → 특수 → 일반이다. 중복 점수를 주지 않는다. 특수 분류: 저격몹, 함정몹, 산성 거머리, 지원 캐스터, 영양 도둑, 보물 도주몹, 소화효소 몬스터. 혈전 자체 처치는 몬스터 처치 점수에서 제외한다. 위산 사망/정리 despawn은 점수를 주지 않는다.

점수 조정 시 `RunScoreData.Total`, `CloudCode/QaRun.js`의 weights/성공 보너스, `ApothecaryUI.Leaderboard.cs` 안내 문구와 테스트 기대값을 함께 수정하고 Cloud Code를 다시 게시한다. 기존 최고기록은 자동 재산정되지 않으므로 QA 이후 규칙 변경 시 새 시즌 ID/보드를 사용하는 것이 안전하다.

## 화면과 동작

- 메인 왼쪽 하단 10줄: 상위 9명 + 내 순위. 내가 상위 9명 안에 있으면 중복 없이 상위 10명. 아직 기록이 없으면 내 기록 없음.
- 닉네임 2~12자(문자·숫자·밑줄·하이픈), 이름 변경/점수 안내 버튼. Unity 계정 제재 알림이 있으면 안내 화면에서 확인한다.
- 실제 이름에 붙는 Unity 식별용 #태그는 화면에서 숨기고, 입력한 이름을 리치텍스트로 해석하지 않는다.
- 결과창에 이번 탐험 총점과 등록 상태가 나온다. 실제 클리어/실패 확정 때만 제출한다.
- 출전 전 서버 티켓을 발급하고 종료 시 사건별 횟수를 보낸다. 서버가 점수를 계산하고 Best 정책으로 최고기록만 유지한다.
- 메인 진입/결과 이후/메인 체류 120초마다 조회한다. 몬스터 처치마다 네트워크 요청하지 않는다.
- 온라인 출전 뒤 전송 실패 시 기기에 대기 기록을 저장하고 다음 연결 때 재전송한다. 새 출전은 이전 종료 전송 이후 시작한다. 서버는 중복 종료 요청으로 점수가 변하지 않도록 확정 데이터를 보관한다.
- 오프라인 상태로 출전한 판은 순위에 등록하지 않는다. 게임은 계속 이용할 수 있으며 메인에는 저장된 순위임을 표시한다.
- 테스트 단축키(위산, 보스/혈전/소화효소 강제 소환 등) 사용 판은 연습 기록으로 제외한다.

## QA 운영과 한계

무료 사용량 안에서 운영하며 자체 노트북 서버를 상시 켤 필요는 없다. 게임 배포 서버와 UGS 랭킹 서버는 별개다. Unity 무료 할당량/정책은 대시보드에서 확인한다. 유료 결제 없이도 한도 초과 등으로 서비스가 중단될 수 있으므로 QA 중 사용량을 확인한다.

익명 계정은 같은 기기/브라우저 저장소에서 유지된다. 브라우저 데이터 삭제, 다른 브라우저/기기, 다른 WebGL 호스트 주소에서는 별도 계정으로 보일 수 있다. Steam 출시 시 동일 계정에 Steam 자격을 연결하는 별도 작업이 필요하며 현재는 구현하지 않았다.

직접 Leaderboards 쓰기 차단, 서버 계산, protected 출전 티켓, 횟수·시간·성공 조건 검증이 적용되어 있다. 전투 전체를 서버에서 재현하지 않으므로 변조 클라이언트의 그럴듯한 횟수까지 증명하는 완전한 부정행위 방지 시스템은 아니다. 소규모 QA용이며 출시용으로 추가 검토한다. 클라이언트에는 관리자 키/서비스 계정 비밀키를 넣지 않는다.
