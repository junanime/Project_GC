# 지스타 2026 체험판 운영·개발 안내

작성 기준: 2026-11-16 · 전용 브랜치 `gstar/2026-demo`

이 문서는 구현된 규칙과 현장 운영 방법을 설명합니다. 실행 검증의 범위와 결과는 마지막 검증 기록에 정리했습니다.

## 1. 참가자에게 보이는 진행 순서

1. **출전준비**에서 캐릭터·무기·유물·시작 아이템을 고르고 스테이지 0(구강), 1(위장), 2(대장) 중 하나로 출전합니다.
2. 각 스테이지의 종료 연출까지 재생한 뒤 **01 기록·랭킹**이 나옵니다. 다음 스테이지로 자동 이동하지 않습니다. 성공 제목은 **스테이지 클리어!**, HP가 0이 된 실패 제목은 **스테이지 클리어 실패**입니다.
3. 이름 또는 별명을 입력하고 **등록하기**를 누르면 해당 PC에 기록이 저장됩니다. **전화번호는 선택 사항**이며, 입력할 때만 경품 안내용 저장 동의를 받습니다. 번호를 비워 두어도 순위 등록이 가능합니다. 내 전체 순위와 각 스테이지 TOP 3를 볼 수 있습니다. **점수 내역**에서 계산 근거를 확인합니다. 등록하지 않고 **다음**으로 넘어가는 것도 가능합니다.
4. **02 다음 도전**에서 각 스테이지 아래의 **도전하기**로 바로 재도전합니다. 같은 스테이지를 반복해도 됩니다. **캐릭터 변경**은 출전준비로 돌아가 캐릭터·장비를 바꾸며, **체험 마치기**는 종료 화면으로 이동합니다.
5. **03 체험 종료**는 설문 QR 및 홈페이지 QR을 보여주는 화면입니다. 참가자가 떠난 뒤 직원이 다음 참가자를 준비합니다.

### 도전 기회

- 참가자 한 명에게 **총 3회**를 줍니다. 별도의 10분 제한은 없습니다.
- 출전을 시작할 때 1회 차감합니다. 승리·실패 모두 한 번의 도전입니다.
- 첫 도전 후 2회, 두 번째 도전 후 1회가 남습니다. 남은 **1**은 빨간색으로 강조합니다.
- 캐릭터 변경이나 출전준비 왕복으로 횟수가 복구되지 않습니다. 시작 아이템 선택은 같은 참가자의 재도전 동안 유지되며, 직접 바꿀 수 있습니다.
- 실제 플레이가 시작되기 전 로딩 실패는 기회를 돌려줍니다. 플레이 시작 후 강제 종료된 도전은 사용한 기회로 남습니다. 프로그램 재실행만으로 새 참가자가 되지 않습니다.
- 0회가 되면 도전하기·캐릭터 변경은 사용할 수 없고 체험 마치기로 진행합니다.

## 2. 직원 운영 절차

### 다음 참가자 시작

1. 참가자가 설문을 마친 **체험 종료 화면**에서 **F9**를 누릅니다.
2. **직원용 · 다음 참가자 준비** 패널에서 **새 참가자 시작**을 누릅니다.
3. 출전준비로 돌아가며 도전 기회는 3회가 됩니다. 이전 참가자의 입력 중인 이름·전화번호와 시작 아이템 선택을 비웁니다.

이 조작은 누적 랭킹과 이미 등록된 경품 연락처를 삭제하지 않습니다. F9는 종료 화면에서만 직원 패널을 열고 닫습니다. 일반 게임 중 보스·혈전 소환, 실버 추가, 경험치 추가 등의 개발용 단축키는 지스타 버전에서 차단됩니다.

### 기록 내보내기와 하루 종료

- 직원 패널의 **경품 기록 저장**을 누르면 아래 CSV 3종을 갱신합니다. 참가자가 체험 마치기를 눌렀을 때도 내보내기를 시도합니다.
- 저장 완료 메시지와 저장 경로를 확인한 다음 프로그램을 종료하고 **GStar2026 폴더 전체**를 날짜별 보관 폴더나 운영용 저장 장치로 복사합니다.
- 행사 기간에는 같은 PC와 같은 Windows 계정으로 실행합니다. 프로그램 설치 폴더를 옮겨도 동일한 계정의 아래 저장 경로에 기록이 남습니다.
- 새 버전으로 교체할 때도 기록 폴더를 먼저 복사해 두고, 게임을 종료한 상태에서 실행 파일 묶음을 교체합니다. 기록 폴더를 삭제하거나 다른 PC의 기록으로 덮어쓰지 않습니다.
- 저장 오류가 표시되면 기존 파일을 유지하고 저장 공간과 폴더 접근을 확인합니다. 코드가 손상된 랭킹 파일을 자동으로 빈 기록으로 덮어쓰지는 않습니다.
- 게임 중이나 메뉴에서 **F8**을 누르면 QA용 플레이 자료를 한 번에 내보내고 저장 경로를 약 7초간 안내합니다. 종료 화면의 F9 직원 패널에서도 **QA 자료 저장 · F8** 버튼으로 같은 동작을 실행할 수 있습니다. QA 자료에는 이름·전화번호가 포함되지 않습니다.

### 재화 전환

- 일반 필드에서는 골드·실버를 바닥에 떨어뜨리지 않고 획득 시점에 점수로 바로 더합니다. 몬스터·보스·보물상자·항아리·이벤트·보물 몬스터 보상이 이 경로를 사용합니다.
- 골드 획득 배율과 골드 러시 효과는 점수 전환 전에 한 번만 적용합니다. 은색으로 보이던 `Silver2` 코인은 골드 2 단위이며, 별도의 실버 지갑 보상과 중복 계산하지 않습니다.
- 기존 코인 수집 미니스테이지만 **민트색 점수 토큰**을 직접 수집합니다. 토큰을 생성하는 순간에는 점수를 주지 않고, 실제로 수집한 토큰만 더합니다.
- 경험치 보석과 일반 아이템 보상은 유지합니다. 두더지는 경험치를 먹고 땅으로 숨는 행동을 유지하며, 처치 보상의 골드 부분만 점수로 바뀝니다.
- 게임 중 기존 골드 표시 위치에는 누적 점수가 나옵니다. 점수는 상점에서 소비하지 않습니다.

## 4. 스테이지별 랭킹과 경품 대상

- **구강·위장·대장 각각 독립된 순위표**이며, 스테이지마다 1·2·3위를 경품 대상으로 내보냅니다. 상품이 정해지기 전까지 화면에는 선물상자 이미지와 상품 증정 문구만 사용합니다.
- 같은 전화번호는 같은 참가자로 취급하고, 스테이지마다 **개인 최고 점수 한 개**만 순위에 올립니다. 여러 번 도전해 한 사람이 같은 스테이지의 TOP 3를 모두 차지하지 않습니다.
- 전화번호를 입력하지 않은 참가자는 현재 체험의 참가자 식별값으로 묶습니다. 같은 체험에서 별명을 바꾸거나 재도전해도 스테이지별 최고 기록 하나만 올라갑니다. 서로 다른 참가자가 같은 별명을 쓰는 것은 허용됩니다. 번호를 남기지 않은 경품 대상은 연락처 CSV가 비어 있으므로 현장 확인이 필요합니다.
- 동점이면 해당 점수의 도전을 먼저 완료한 기록이 앞섭니다. 완료 시각까지 같을 때는 기록 ID로 순서를 고정합니다. 플레이 시간이 짧다고 별도의 점수를 더하지 않습니다.
- 중복 등록 버튼 클릭은 새 점수를 만들지 않습니다. 이미 등록한 한 도전의 연락처는 다시 바꿀 수 없습니다.
- 화면에는 이름·점수·순위가 표시되고 전화번호는 표시하지 않습니다. **내 순위**도 해당 스테이지의 개인 최고 기록 기준입니다. 이번 점수가 최고 기록보다 낮으면 그 사실을 안내합니다.
- 정상 출전 절차를 거치지 않은 실행, 별도로 제외 표시된 개발 테스트 기록은 순위에 등록되지 않습니다. 스테이지 1의 필드 소환 제단은 지스타 버전에서 테스트 선택창 대신 그 판에 미리 정해진 보스를 소환합니다.

## 5. 저장 위치와 파일

지스타 빌드 제품명은 **24시간의 사투 지스타2026**이며, 일반 게임과 저장 경로를 분리합니다. 현재 회사명 설정은 `DefaultCompany`입니다.

Windows 탐색기 주소창에 다음을 입력하면 됩니다.

```text
%USERPROFILE%\AppData\LocalLow\DefaultCompany\24시간의 사투 지스타2026\GStar2026
```

| 파일 | 용도·공개 범위 |
|---|---|
| `leaderboard.json` | 모든 완료 기록과 등록 정보를 보관하는 원본. 전화번호 포함, 운영자용 |
| `leaderboard.json.bak` | 랭킹 복구용 백업. 전화번호 포함, 운영자용 |
| `leaderboard.json.tmp` | 저장 중 사용하는 임시 파일. 복구 확인 대상이므로 장애 직후 임의 삭제 금지 |
| `visitor-session.json` | 현재 참가자의 남은 기회·진행 상태·입력한 연락처. 운영자용 |
| `visitor-session.json.bak` | 현재 참가자 상태의 백업. 운영자용 |
| `all-runs-private.csv` | 모든 도전의 점수 내역·등록 여부·이름·전화번호·제외 사유. 운영자용 |
| `prize-top3-private.csv` | 스테이지별 TOP 3와 경품 연락용 전화번호. 경품 담당자용 |
| `ranking-public.csv` | 스테이지·순위·이름·점수. 전화번호 없는 공개용 순위표 |

랭킹은 이 PC의 파일로 동작하며 온라인 랭킹 서버를 필요로 하지 않습니다. JSON의 무결성 확인값은 저장 손상 검사에 쓰이며 연락처 암호화를 의미하지 않습니다. 개인 파일·백업·전체 기록 CSV는 공개 화면이나 공유용 자료에 올리지 않고, 공개할 때는 `ranking-public.csv`를 사용합니다.

## 6. 해금 및 유지하는 제한

- 허용된 캐릭터·무기·유물은 지스타 체험 중 사용할 수 있습니다. 출전준비 아이템과 필드 상점 구매·새로고침은 무료입니다.
- 현재 아이템 카탈로그 66종 중 명시적으로 은퇴 처리한 8종을 제외한 **58종**을 제공합니다. 시작 아이템은 계속 **최대 2개**입니다. 필드 상점의 보유 아이템 중복 방지·재고·구매 후 퇴장 규칙도 유지합니다.
- 증강은 무기 해금 부족으로 막히지 않게 합니다. 현재 도전에서 필요한 본체 보유 조건, 최대 강화 횟수, 등급 확률, 제작자가 꺼 둔 기능은 유지합니다. 모든 강화 효과를 시작부터 한꺼번에 지급하는 방식은 아닙니다.
- 일반 프로필에 영구 해금이나 실버를 지급하지 않습니다. 체험판의 무기·유물 선택은 임시 상태로 처리합니다.

| 유지하는 제외·제한 | 구체적인 대상 |
|---|---|
| 은퇴 아이템 | `octoberId` 9, 10, 19, 23, 35, 40, 45, 53 |
| 중복으로 은퇴한 유물 | `lotus_chips` |
| 사용 불가 무기 | `Honey`, `WoodNeedle` |
| 사용 불가 고귀 증강 | `PoisonContagion`, `NeedleShotgun` |
| 개별 무기 설정 | 기존 `Enabled` 해제 및 체험 중 사용자가 끈 무기 유지 |
| 출전준비 판매 제한 | `canBuyInLobby` 조건 유지. 현재 66종 카탈로그는 모두 true이며 은퇴 8종을 별도로 제외 |
| 제작 중·비활성 기능 | 기존 등급 확률·조건·별도 비활성 보상 설정 유지 |

## 7. 설문·홈페이지 QR 추가

현재 두 QR 영역은 비어 있습니다. 주소를 확정한 뒤 아래 이름으로 실제 QR 이미지를 추가하고 다시 빌드합니다.

```text
Assets/Resources/GStarDemo/survey-qr.png
Assets/Resources/GStarDemo/homepage-qr.png
```

- 두 파일은 Unity에서 **Sprite (2D and UI) / Single**로 가져옵니다. QR 주변의 흰 여백을 포함하고, 압축을 사용하지 않습니다.
- 종료 화면은 각각 `GStarDemo/survey-qr`, `GStarDemo/homepage-qr`를 읽습니다. 설문은 큰 왼쪽 영역, 홈페이지는 오른쪽 신이의 불꽃 배경 위에 놓입니다.
- 실제 행사 모니터에서 휴대폰으로 두 QR이 각 목적지로 연결되는지 확인합니다. QR 파일이 없으면 해당 영역은 빈 상태로 유지됩니다.

## 8. Windows 실행본 제작·설치

Unity **2022.3.62f3**를 사용합니다. 지스타 전용 브랜치에서 실행해야 하며, `Assets/Resources/GStarDemo/enabled` 표시 파일로 체험판 기능을 켭니다.

PowerShell 예시:

```powershell
& 'C:\Program Files\Unity\Hub\Editor\2022.3.62f3\Editor\Unity.exe' `
  -batchmode -quit `
  -projectPath 'D:\GameDev\ProjectCopies\GitHub\Project_GC' `
  -executeMethod Vampire.Tests.Editor.GStarBuild.Run `
  -logFile 'D:\GameDev\ProjectCopies\GitHub\Project_GC\Logs\GStar-Windows-Build.log'
```

`GStarBuild.Run`은 Windows 64비트 실행본을 만들며, 이번 빌드에서 Steam 전용 설정을 제외하고 개발 빌드 옵션을 끕니다. 빌드 후 프로젝트의 제품명·설정은 원래대로 복원합니다.

결과 폴더와 실행 파일:

```text
Builds/GStar2026-Windows/
└─ 24tu-GStar2026.exe
```

**설치할 때는 `GStar2026-Windows` 폴더 전체를 복사합니다.** exe만 복사하면 실행에 필요한 Data 폴더·Unity 라이브러리·런타임이 빠집니다. 대상 PC에서는 그 폴더 안의 `24tu-GStar2026.exe`를 실행하거나 바로가기를 만듭니다.

일반 게임과 기존 페스티벌 실행본을 덮어쓰지 않는 별도 설치입니다. 지스타 기능 변경은 전용 브랜치에서 관리합니다. 이후 일반 버전으로 옮길 때는 지스타 표시 파일·세션·랭킹 동작을 포함할지 별도로 결정해야 합니다.

## 9. F8 QA 자료: 캐릭터 선택·성공률·플레이 행동 분석

랭킹 및 경품 연락처 파일과 별개로 게임 플레이만 기록합니다. 랭킹에 등록하지 않은 도전도 포함하며 **개인 이름·별명·전화번호는 기록하지 않습니다.** `character_name`은 참가자 이름이 아니라 아시·혁이·아리·신이 등의 게임 캐릭터 이름입니다. `run_id`와 `session_id`는 도전 및 체험을 구분하기 위한 식별값입니다.

저장 위치:

```text
%USERPROFILE%\AppData\LocalLow\DefaultCompany\24시간의 사투 지스타2026\GStar2026\analytics
```

F8을 누르면 그 안의 **exports** 폴더에 다음 10개 파일을 함께 만듭니다. 다시 누르면 현재까지의 누적 자료로 갱신하므로 폴더 전체를 복사해 전달하면 됩니다.

| 파일 | 내용 |
|---|---|
| `runs.jsonl` | 한 줄당 한 도전의 원본 측정값. 분석 도구용 |
| `events.jsonl` | 한 줄당 한 행동·선택·이벤트. 시간순 원본 |
| `runs.csv` | 도전별 캐릭터·스테이지·시작 장비·결과·처치·대시·스킬·피해·레벨·플레이 시간 |
| `character-summary.csv` | 캐릭터별 실제 출전 횟수, 성공/실패/포기/중단 횟수, 성공률 및 평균값 |
| `stage-summary.csv` | 스테이지별 같은 지표 |
| `character-stage-summary.csv` | 캐릭터와 스테이지 조합별 같은 지표 |
| `events.csv` | 전체 행동·이벤트를 엑셀에서 읽는 버전 |
| `choices.csv` | 증강·혈전 보상·유물·아이템 등의 제시 후보와 선택/획득 기록 |
| `choice-counts.csv` | 이벤트 종류와 선택 항목별 기록 횟수, 해당 도전 수 |
| `offered-counts.csv` | 실제로 제시한 후보별 제시 횟수와 해당 도전 수 |

### 도전별 측정 항목

- 캐릭터 ID·이름, 스테이지 번호, 시작 무기 ID·유물 ID·아이템 ID/이름, 시작·종료 UTC 시각.
- 일반·특수·엘리트·미니보스·보스 처치 수를 구분합니다. 게임 점수 집계에 실제로 반영된 횟수를 사용합니다.
- 입력 시도 횟수가 아니라 **실제로 발동한 대시와 액티브 스킬 횟수**를 기록합니다. 신이도 실제 발사/충전 동작 시작 경로에서 셉니다.
- 누적 가한 피해·받은 피해·회복량은 게임의 `StatsManager` 측정값입니다. 측정 객체를 찾지 못하면 `combat_stats_available=false`이며 CSV 피해 칸은 비웁니다. 측정하지 못한 값을 0으로 추정하지 않습니다.
- 플레이 시간, 종료 시 레벨, 점수, 재화에서 전환한 양, 미니스테이지 성공과 과충전 성공 횟수.

### 결과와 평균의 의미

| `status` | 의미 |
|---|---|
| `active` | F8 시점에 아직 플레이 중 |
| `clear` | 스테이지 클리어 |
| `fail` | HP 0 등 게임의 실패 처리로 종료 |
| `abandoned` | 플레이 중 출전준비로 돌아가거나 종료하는 등 중도 포기 |
| `interrupted` | 종료 처리가 기록되기 전에 프로그램이 중단되어, 재시작 때 미완료 기록을 복구 |

`selected_runs`는 실제 플레이를 시작한 출전 횟수입니다. 출전준비 화면에서 캐릭터를 잠깐 눌러 본 횟수는 포함하지 않습니다. `clear_rate_completed`는 **clear ÷ (clear + fail)**이며, 포기·강제 중단·현재 플레이 중인 도전은 이 분모에서 제외합니다. 완료된 도전이 없으면 빈칸입니다.

성공과 실패의 평균 처치 수·대시 수·플레이 시간을 각각 `clear_avg_*`, `fail_avg_*`로 제공합니다. `all_avg_*`는 포기·중단·현재 진행까지 포함한 전체 출전의 현재 측정값입니다. 이 두 평균을 같은 의미로 비교하지 않습니다.

### 시간순 선택·이벤트 기록

각 행에는 도전 ID, 도전 안의 순서 `sequence`, 경과 시간 `elapsed_seconds`, UTC 시각, `event_type`, 항목 ID, 설명 `detail`, 실제 제시 후보 `offered_options`가 있습니다. 보상창에서 시간이 멈춘 상태로 선택해도 기록합니다.

| 이벤트 계열 | 주요 종류 |
|---|---|
| 증강 | `augment_offered`, `augment_choice` |
| 혈전 보상 | `bloodclot_reward_offered`, `bloodclot_reward_choice` |
| 보급 유물 | `supply_relic_offered`, `supply_relic_choice`, `supply_relic_deferred` |
| 상점 | `shop_offered`, `shop_reroll`, `shop_purchase` |
| 필드 이벤트 | `field_event_start`, `field_event_end`, `field_reward` |
| 미니스테이지·과충전 | `mini_enter`, `mini_success`, `overcharge_success` |
| 보스 | `boss_summon`, `boss_defeated` |
| 액티브·도전 시작/끝 | `active_skill`, `run_started`, `run_ended` |

제시 후보는 기록 가능한 실제 선택창에서만 채웁니다. 빈 후보 칸을 임의 후보로 보충하지 않습니다. `choice-counts.csv`를 볼 때는 `augment_choice`처럼 원하는 **선택 이벤트 종류**로 필터링하고, `offered-counts.csv`와 비교합니다. 후보를 다시 제시한 횟수도 세기 때문에 새로고침을 많이 한 도전에서는 제시 횟수가 커질 수 있습니다.

### 저장·복구 방식과 범위

- `analytics/runs/run-<ID>.json`에 도전별 측정값을 저장합니다. 약 5초마다 저장하며, 선택·이벤트·도전 종료·F8 시점에도 저장합니다.
- 작은 도전 파일 하나만 임시 파일에서 교체하고 `.bak`을 남깁니다. 전체 행사 기록을 매 프레임 다시 쓰지 않습니다. 종료된 도전은 다시 열거나 덮어쓰지 않습니다.
- 행동은 `analytics/events-live.jsonl`에 즉시 추가·플러시합니다. 비정상 종료로 마지막 줄 일부가 잘렸으면 원본은 보존하고, 내보내기에서 유효한 줄만 사용합니다.
- 프로그램이 중단된 도전은 마지막 저장 시점의 수치로 `interrupted` 처리합니다. 갑작스러운 전원 차단에서는 마지막 저장 이후 최대 약 5초의 대시·피해 등 누적 수치가 남지 않을 수 있습니다. 완료한 도전과 이전 참가자의 누적 자료는 유지합니다.
- **새 참가자 시작**은 QA 누적 자료를 삭제하지 않습니다. 하루 마감 백업에는 `analytics` 폴더도 포함합니다.
