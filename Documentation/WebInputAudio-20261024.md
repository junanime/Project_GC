# 웹 입력·오디오 재검증 · 2026-10-24

## 수정 내용

- 모바일 조이스틱은 UI 포인터 이벤트에만 의존하지 않는다. 실제 InputSystem 터치 시작 상태와 브라우저 캔버스의 터치 좌표를 보완 경로로 사용한다. 최상위 UI가 조이스틱인지 확인한 후 해당 손가락만 이동을 소유한다. 다른 손가락의 대쉬·액티브 입력/해제가 이동을 해제하지 않는다.
- 브라우저 좌표는 캔버스 표시 영역으로 정규화한 뒤 Unity 화면 크기로 환산한다. DPR·브라우저 확대·렌더링 해상도 차이를 보정한다. 화면 회전 안내, 일시정지, 백그라운드 전환, 손가락 취소 시 입력을 해제한다.
- 모바일 이동 중 키보드/게임패드의 취소 콜백이 조이스틱 방향을 덮어쓰지 않도록 했다.
- 기존 오디오 소스 파일은 교체하지 않는다. 웹 빌드에서만 128개 오디오를 최고 품질, 원본 샘플레이트·채널 유지, 사전 로딩/디코딩으로 임포트한다. Unity 2022.3의 WebGL 오디오 변환은 AAC이므로 무손실 PCM과 동일하다고 표현하지 않는다. 빌드 종료 시 제작용 임포트 설정을 복원한다.
- 각 빌드에 `audio-sources.sha256`을 남겨 PC/모바일이 같은 원본을 사용했는지 확인한다. 해당 파일은 공개 서버의 허용 목록에 포함하지 않는다.
- 기존 Unity AudioContext를 사용자 터치/키 입력에서 재개한다. 별도 컨텍스트나 중복 음악 플레이어를 만들지 않는다. 음악은 디코딩과 브라우저 소리 허용이 완료된 뒤 현재 필요한 한 레이어만 재생한다. 종료한 게임 음악은 자동 복구하지 않는다.
- 보스 종료와 증강 선택창이 겹칠 때 필드 음악이 선택창 아래에서 재개되던 경로를 막았다.
- 구형 지도 오브젝트의 누락 스크립트 2개를 제거했다. 현재 탐험 지도/확대 기능은 유지한다. 에디터 캡처의 우측 상단 언어 메뉴는 Unity Localization의 편집기 전용 표시여서 배포 게임 오류로 분류하지 않는다.
- 미니 스테이지 중 스폰 정지 로그를 매 프레임 출력하던 코드를 정지 진입 시 한 번만 기록하도록 바꿨다. 스폰 타이밍/수량은 바꾸지 않는다.
- 튜토리얼의 종류 제목을 스티치 배너의 불투명 영역 안으로 옮기고 긴 제목은 영역에 맞게 축소한다.
- 증강 선택 연출이 생성 이전의 프레임 시간까지 더해 약 1.36초 만에 끝나는 사례를 재현했다. 준비 완료 시점의 실제 시각을 기준으로 1.5초를 계산하도록 수정했다. 수동 시안 샘플링과 기존 궤도·침 수·카드 뒷면은 유지한다.

## 검증 방법과 한계

- 실제 Unity 씬에서 InputSystem Touchscreen 입력을 주입하고 UI 레이캐스트, 손잡이, 플레이어 좌표, 대쉬 차지, 액티브 상태로 검증한다. 입력 함수를 직접 호출하는 검사와 구분한다.
- UI 포인터 모듈을 중지한 상태에서도 실제 터치 시작/해제가 이동을 복구하는지 검사한다. 브라우저 경로는 정규화 좌표·손가락 소유권·회전/백그라운드 복귀를 별도로 검사한다.
- 브라우저 이벤트 연결과 오디오 재개 코드는 Node 회귀 검사로 중복 설치·취소·이벤트 정리까지 확인한다.
- 원본 오디오 해시와 임포트 설정을 확인한다. 메인/출전준비/필드/보스/증강/종료 전환에서 재생 상태와 음악 중복을 검사한다.
- 실제 휴대폰 및 Safari 실기기 검증은 별도로 필요하다. 이 문서의 자동화 검사를 실기기 청음 또는 전 기종 호환 검증으로 간주하지 않는다.

## 배포

공개 주소와 스테이지 1 종료 범위를 유지한다. 새 PC/모바일 빌드 검증 후 서버의 활성 경로만 교체하고, 이전 빌드 파일은 이미 플레이 중인 사용자의 요청을 위해 보존한다. 소스/빌드/최종 검사 결과는 `WebRelease-20261024.md`에 기록한다.

배포 완료: 게임 소스 `10ec95e`, PC 약 564 MB / 모바일 약 403 MB. 기존 공개 주소에서 양쪽 빌드 버전과 파일 응답을 확인했고, 실제 공개 PC 화면의 인트로→메인→출전준비와 로비 음악 Loaded/Pitch=1을 확인했다. `work/WebInputAudio-20261024/public-preparation.png`에 실제 화면을 보관한다.
