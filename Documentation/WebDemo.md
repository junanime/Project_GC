# 24시간의사투 — 브라우저 테스트판

## 웹 데모 규칙

- 게임을 새로 실행할 때 실버가 10,000개 미만이면 10,000개로 보충합니다.
- 10,000개보다 많이 모은 실버와 기존 해금 내용은 유지합니다. 해금은 출전 준비에서 직접 선택합니다.
- 플레이 도중 또는 로비로 돌아올 때에는 다시 보충하지 않습니다. 브라우저 페이지를 새로 열거나 새로고침하면 새 실행으로 취급합니다.
- 이 지급 규칙은 웹 데모 빌드에만 적용합니다. Windows 설치판 및 Unity 에디터의 기존 저장에는 자동 지급하지 않습니다.
- 영구 성장 저장은 해당 브라우저·사이트의 로컬 저장소를 사용합니다. 다른 기기/브라우저와 동기화되지 않으며, 사이트 데이터 삭제나 비공개 창에서는 보존되지 않을 수 있습니다. 진행 중인 전투는 이어하기를 지원하지 않습니다.

## 플레이

공유 기본 주소는 기기 선택 화면입니다. 게임 패널 안에서 **PC버전 / 안드로이드 버전 / 아이폰 버전**을 선택하면 해당 플레이어를 불러옵니다. 선택 전에는 대용량 게임 파일을 받지 않습니다. 현재 기기를 추천 표시하고 다른 기기 버튼을 누르면 올바른 버전을 안내합니다.

- PC: Chrome 또는 Edge, 키보드·마우스. 게임 오른쪽 한지 수첩에 조작법을 표시하며 전체화면에서는 게임만 표시합니다.
- 안드로이드: Chrome 권장, 가로 화면의 터치 조작. 아이폰과 동일한 ASTC 모바일 게임 파일을 재사용합니다. 그래픽 지원 여부는 시작 전에 검사합니다.
- 아이폰: Safari로 열도록 안내합니다. 카카오톡 등 앱 내부 브라우저는 외부 브라우저로 열도록 안내하고 시작을 막습니다. 아이폰 Chrome 등을 무조건 불가능하다고 표시하지는 않으며 정상 동작을 보장하지 않는다고 명시합니다.
- 휴대폰에서는 수첩을 선택 화면 아래로 배치하고 플레이 시작 후 숨깁니다. 기존 `/mobile/` 직접 링크는 계속 사용할 수 있습니다.
- PC 플레이어는 `/play-pc.html?embed=1`, 모바일은 `/mobile/?device=android` 또는 `iphone`입니다. 기존 플레이어와 같은 URL 디렉터리를 사용하여 Unity 브라우저 저장 경로가 바뀌지 않도록 합니다. 게임 바이너리는 재빌드하지 않았습니다.

구현: `Tools/Distribution/WebPortal/index.html`(벡터 기기 아이콘·선택 UI·수첩), `Share-WebDemoServer.cjs`의 선택적 `portalRoot`. `Prepare-WebPortal.cjs`는 기존 HTML을 백업한 뒤 최신 셸만 적용합니다. 배포할 때 기존 게임 경로와 해시 에셋을 유지합니다. 화면 검사 `Test-WebPortal.cjs` 45개, 모바일 셸 11개, 서버 16개 통과. 실제 PC 및 안드로이드 터치 에뮬레이션에서 기존 컴파일된 게임 로비와 전체화면을 확인했습니다. 실제 Android/iPhone 기기 테스트를 대신하지 않습니다. 검증·롤백 자료: `D:/Project_GC/work/WebPortal-20261007`.

- PC 빌드를 유지하고 별도 ASTC 모바일 웹 빌드를 `/mobile/`에 제공합니다. APK/IPA 설치나 Apple 개발자 계정은 필요하지 않습니다.

- 왼쪽 빨간 반투명 조이스틱으로 이동, 오른쪽 조이스틱으로 조준/충전합니다. 대쉬·상호작용 버튼, 기존 스킬 아이콘 및 상하좌우 네 아이템 슬롯을 터치합니다. 상태/설정 버튼도 표시됩니다.

- 다운로드 시작 전 안내와 로딩 후 터치 시작 단계를 둡니다. WebGL 2 / ASTC 미지원 기기는 다운로드 전에 안내합니다. 네이티브 전체화면 지원 여부와 관계없이 플레이합니다.
- 기존 웹의 세션별 10,000 실버 보충 규칙을 유지합니다. 브라우저 저장이며 계정 동기화나 전투 중 이어하기가 아닙니다.
- Unity 2022.3의 모바일 WebGL은 공식 지원 대상이 아닙니다. 기기별 메모리 부족·재로딩·발열·음량은 실제 아이폰 QA가 필요하며, PC의 터치 에뮬레이션 통과가 Safari 실기기 검증을 뜻하지 않습니다. 참고: [Unity 브라우저 호환성](https://docs.unity3d.com/2022.3/Documentation/Manual/webgl-browsercompatibility.html).
- 임시 공유는 노트북 서버와 인터넷이 켜져 있을 때만 유효합니다. PC 기본 링크의 빌드와 별도로 관리합니다.

검증 기록: `Builds/WebDemo-Mobile-20261007-r2` 빌드 성공(보고서 525,276,439 bytes). 웹 셸 11개·배포 서버 16개 검사 통과. 에디터 3회 씬 진입 및 Chrome 터치 에뮬레이션에서 로비/10,000 실버, 이동+조준 동시 입력, 대쉬, 설정, 회전, 로비 복귀/재입장, 실패 후 다시하기를 확인했습니다. 아이템 UI를 원래 씬의 안전 영역 안에 유지하여 재입장 시 중복 표시를 수정했습니다. 외부 HTML 일치와 실행 JavaScript/Wasm 내용, 4개 핵심 에셋 응답, 기존 PC 버전 유지도 검증했습니다. 실제 iPhone/Safari·15분 완주·발열·음량 청취는 미검증입니다. 큰 에셋 캐시는 브라우저 용량 제한에 따라 재다운로드될 수 있습니다. 배포 증거는 `D:/Project_GC/work/SafariWeb-20261007/deployment.json`에 보관합니다.

## 파일과 업로드

`index.html`과 `Build`, `StreamingAssets` 등 생성된 파일 전체가 한 묶음입니다. HTML 파일만 공유하면 게임이 실행되지 않습니다.

- 정적 HTTPS 호스팅에 폴더 전체를 업로드합니다. 압축파일 루트에 `index.html`이 있어야 합니다.
- `.unityweb`은 Gzip 압축과 Unity 자체 압축 해제를 사용합니다. 서버에서 Content-Encoding을 임의로 덧붙이지 않아도 됩니다.
- `index.html`은 장기 캐시하지 않는 것을 권장합니다. 빌드 데이터는 해시 파일명을 사용합니다.
- GitHub에는 소스·설정·검증 도구만 보관하고 생성된 웹 빌드/설치파일은 올리지 않습니다. 외부 공유 서버 배포는 별도 단계입니다.
- `index.html`을 더블클릭하는 `file://` 실행은 지원하지 않습니다. 로컬 HTTP 서버 또는 호스팅 주소로 실행해야 합니다.
- Windows에서 압축을 모두 푼 뒤 `Launch-WebDemo.cmd`를 실행하면 로컬 서버와 브라우저가 열립니다. 별도 Python/Node 설치는 필요하지 않습니다. 실행 창을 닫으면 서버도 종료됩니다. 이 주소는 현재 PC 전용이며 외부 공유 링크가 아닙니다.

## 재빌드

Unity 2022.3.62f3의 WebGL Build Support가 필요합니다. 타깃을 WebGL로 전환한 뒤 `24투 > Build browser demo (10,000 silver)`를 실행합니다.

자동화: `-batchmode -buildTarget WebGL -projectPath <프로젝트> -executeMethod Vampire.Editor.WebDemoBuild.Run -logFile <로그>`.
`PROJECT_GC_WEB_OUTPUT`으로 출력 폴더, `PROJECT_GC_SOURCE_COMMIT`으로 빌드 기록의 기준 커밋을 지정합니다. 기본 출력은 `Builds/WebDemo`입니다.
빌드 도구가 `PROJECT_GC_WEB_DEMO`를 해당 빌드에만 정의합니다. 기존 PC 빌드의 설정과 실버 정책은 유지합니다.

모바일 QA 빌드는 추가 환경 변수 `PROJECT_GC_WEB_MOBILE=1`을 사용합니다. `24tuMobileWeb` 템플릿, `PROJECT_GC_MOBILE_WEB` 정의, ASTC 하위 타깃 및 큰 텍스처의 ASTC 4x4 압축을 사용합니다. 원본 이미지 크기·프레임 분할은 바꾸지 않습니다. 터치 UI는 브라우저의 모바일 기기 판정에 의존하지 않고 이 빌드에서 활성화됩니다.

`Share-WebDemoServer.cjs`는 설정의 `gameRoot`와 선택적 `mobileRoot`를 각각 `/`, `/mobile/`로 제공합니다. `previousRoots`/`previousMobileRoots`의 해시 에셋은 이전 클라이언트 로딩용으로 유지할 수 있습니다. 런타임 에셋만 허용하며 소스·배포 도구·저장 파일은 노출하지 않습니다. 모바일의 실제 Gzip 파일에만 `Content-Encoding: gzip`을 설정하여 브라우저 네이티브 압축 해제를 사용합니다.

웹 셸 검사: `Test-MobileWebShell.cjs` (Unity 로더 대역 사용). 서버 검사: `Test-ShareWebServer.cjs <기존 웹 빌드> <검사 출력 폴더>`. `MobileWebBrowserQA.cjs`는 로컬 전용 터치 에뮬레이션 검사이며 실제 Safari와 다릅니다.

웹 빌드 중 큰 텍스처에 고품질 DXT 압축을 임시 적용합니다. 해상도·스프라이트 분할·필터·원본 이미지는 바꾸지 않으며, 작은 픽셀 아이콘은 무압축으로 유지합니다. 빌드 후 원래 이미지 가져오기 설정을 복원합니다. 강제 종료로 복원이 중단되었다면 `24투 > Restore web build texture imports`로 `Library/WebDemoTextureBackup.json`의 백업을 복원한 뒤 다음 빌드를 실행합니다.
