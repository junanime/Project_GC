# 페스티벌 PC 데모

이 작업은 `origin/Junhan2`의 `ed67a76`에서 만든 `feature/festival-demo` 브랜치에 있다. 기존 `Project_GC` 작업 폴더의 수정 사항은 포함하거나 변경하지 않는다. 별도 작업 폴더는 `Project_GC-festival-demo`다.

## 참가자 흐름

인트로 → 캐릭터 4종 선택 → 하단 시작 구성 확인 → 기존 로딩 화면 → 60초 생존 → 학과·이름 입력 → 행사 순위 등록 → 다음 참가자.

- 추가 3·2·1 화면은 없다. 기존 `StageEntryLoading`을 최소 3초 보여주며, 실제 장면과 시작 구성이 준비될 때까지 유지한다.
- 로딩 동안 전투와 60초 타이머는 정지한다. 로딩이 끝나면 바로 적이 등장한다.
- WASD 이동, Shift 대시, R 액티브. 신이는 R을 길게 눌러 사용한다.
- 레벨업하면 기존 증강 선택 화면에서 보상을 고른다. 선택 중에는 전투와 60초 타이머가 멈추고, 선택 완료 후 재개된다.
- 경험치 구슬은 데모에서 기본 경험치를 50% 더 지급한다. 흰색 1→1.5, 파랑 2→3, 초록 10→15, 빨강 50→75이며 캐릭터의 경험치 획득 보정은 그 뒤에 적용한다. 일반 모드의 경험치는 유지한다.
- 제한 시간 생존은 성공, 사망은 실패다. 사망 연출 시간을 생존 시간에 더하지 않는다.
- 한 판에 기존 필드 이벤트 한 종류를 무작위 선정하고 25초에 한 번 실행한다. 25초 이전에 종료되면 발동하지 않는다.
- 상점, 혈전 이동, 추가 보급 선택 등 장기 탐험용 초기 필드 오브젝트는 이 모드에서 배치하지 않는다.

## 시작 구성과 밸런스

`Assets/Junhan/Resources/FestivalDemoSettings.json`에서 제한 시간, 적 등장량, 체력 배율, 개체 수 상한, 고귀 퀘스트 목표, 캐릭터별 시작 구성을 조정한다. 화면과 실제 지급은 동일한 설정을 사용한다. 본 게임의 해금이나 장착 저장값을 수정하지 않는다.

| 캐릭터 | 시작 특수 증강 ID | 유물 ID | 아이템 ID | 고귀 보상 |
|---|---|---|---|---|
| 아시 | WindNeedle, Homing, Pierce, ReturnNeedle | feather | 1, 20 | 봉익윤무 |
| 혁이 | IceNeedle, VibrationNeedle, PressureNeedle, Pierce | firm_shield | 12, 2 | 봉명진혼 |
| 신이 | FireNeedle, Explosion, CorrosionNeedle, HungerNeedle | clear_dew | 12, 8 | 봉황파동 |
| 아리 | AcupunctureFormation, MarkNeedle, BipolarNeedle, FiberNeedle | lightning_beat | 1, 2 | 삼중봉익 |

고귀 퀘스트는 20마리 처치, 대시 4회, 액티브 2회 사용의 세 가지다. 모두 완료하면 각 캐릭터의 고귀 증강을 즉시 지급하며 비전서 열기, 완료 버튼, 추가 보상 선택 화면을 요구하지 않는다. 완료 처리에는 중복 방지가 적용된다. 액티브 재사용 시간은 데모에서 최대 24초로 제한하고, 신이는 불씨 18개를 보유한 상태로 시작한다. 최대 체력을 1로 바꾸는 고귀 증강은 자동 보상에 포함하지 않는다.

시작 적 13마리를 나누어 생성하고 초당 생성량을 7→11.2마리로 증가시킨다. 첫 시연 버전의 생성량과 동시 적 수를 약 70%로 낮춘 설정이다. 적 체력은 기본의 1.35→1.85배를 유지한다. 캐릭터별 공격력·공격 속도·체력 보정은 프리셋 설정에서 함께 조정한다.

실제 플레이 난이도는 테스트 결과와 행사 참가자 체험으로 추가 조정한다. 자동 조작 검증은 기능·성능 점검이며 처음 하는 사람의 성공률을 의미하지 않는다.

## 순위

기존 `RunScore`의 처치 점수를 재사용한다. 행사 기록은 기존 온라인 QA 순위에 전송하지 않는다. 기존 온라인 순위는 기기 계정당 최고점이므로 여러 참가자가 공유하는 한 PC의 행사 기록은 별도 누적 장부에 저장한다.

- 입력: 학과 1~40자, 이름 1~24자.
- 저장: 참가자, 캐릭터, 생존 시간, 성공 여부, 점수, 판 식별자, 기록 시각.
- 점수: 기존 점수 + 생존 초당 10점 + 추가 완주 보너스 9,000점. 기존 성공 점수 1,000점을 합해 완주 보너스는 총 10,000점이다.
- 정렬: 생존 성공 우선 → 점수 → 생존 시간 → 먼저 등록된 기록.
- 한 판의 기록 중복 등록을 막고, 다음 참가자 입력값은 비운다.
- 저장 위치: Unity `Application.persistentDataPath` 아래 `Festival/leaderboard-v1.json`.
- 저장은 임시 파일 작성 후 교체하며 직전 정상 파일을 `.bak`으로 보관한다. 저장 실패 시 입력값을 유지한다.
- 네트워크 연결은 필요하지 않는다. 여러 PC 사이의 순위 통합은 이번 구현에 포함하지 않는다.

## PC 성능 범위

기존 적·투사체 풀과 이벤트를 재사용한다. 적의 동시 활성 개체 수는 77마리, 한 프레임당 생성량은 6마리로 제한하고, 프레임 지연 이후 밀린 적 생성이 한 번에 몰리지 않게 한다. 화면 밖 멀리 남은 일반 적은 0.5초마다 최대 12마리씩 풀로 회수해 새 적의 등장 여유를 확보하며, 이 회수에는 처치 점수를 지급하지 않는다. 일반 플레이의 킬별 영구 실버 저장과 치명타별 디버그 로그를 데모에서는 수행하지 않아 전투 중 저장 부하를 줄인다.

## 검증과 빌드

- 통합 검증: Unity 2022.3.62f3에서 `Vampire.Tests.Editor.FestivalDemoSmoke.Run`.
- 검증 결과: `Library/FestivalQA/`의 결과, 전투 측정 CSV, 화면 캡처.
- PC 빌드: 메뉴 `24투/Build festival demo for Windows PC` 또는 `Vampire.Editor.FestivalDemoBuild.Run`.
- 기본 빌드 폴더: `Builds/FestivalDemoPC`. `PROJECT_GC_WINDOWS_OUTPUT`으로 별도 출력 폴더를 지정할 수 있다.
- 페스티벌 빌드는 반복 제작 시간을 줄이기 위해 빠른 LZ4 압축을 사용한다. 일반 빌드의 LZ4HC 설정은 유지한다.
- 실행 파일과 데이터 폴더를 함께 배포한다. 실행 파일만 복사하면 안 된다.

`FestivalDemoSettings.json`의 `enabled`를 끄면 기존 흐름을 사용할 수 있다. 본 게임에 병합하는 작업은 이 데모 작업에 포함하지 않는다.
