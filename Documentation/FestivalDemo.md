# 페스티벌 PC 데모

`feature/festival-demo`는 2026-10-26에 `Junhan2`의 `8380f87`까지 병합했다. 최신 보스 외형·모션·침 부착과 공통 Space 조작을 포함하며, 행사 전용 45초 진행·캐릭터 구성·오프라인 순위 규칙은 유지한다. 별도 작업 폴더는 `Project_GC-festival-demo`다. 이번 행사 실행파일은 Steam 기능을 활성화하지 않는 일반 Windows 빌드다.

## 참가자 흐름

게임 실행 → 캐릭터 4종 선택 → 하단 시작 구성 확인 → 기존 로딩 화면 → 45초 생존 → 학과·이름 입력 → 행사 순위 등록 → 다음 참가자.

- 페스티벌에서는 인트로 영상과 건너뛰기 확인창 없이 바로 캐릭터 선택 화면을 표시한다.
- 추가 3·2·1 화면은 없다. 기존 `StageEntryLoading`을 최소 3초 보여주며, 실제 장면과 시작 구성이 준비될 때까지 유지한다.
- 로딩 동안 전투와 45초 타이머는 정지한다. 로딩이 끝나면 바로 적이 등장한다.
- WASD 이동, Shift 대시, Space 액티브(캐릭터 4종 공통). 신이는 Space를 길게 눌러 화염 분사를 유지한다.
- 경험치를 획득하지 않으며 레벨업 선택창이 열리지 않는다. 일반 몬스터의 경험치 구슬과 초기 필드 구슬도 생성하지 않는다. 다른 아이템 등에서 직접 주는 경험치 역시 차단한다.
- 시작 특수 증강 4종 각각의 오리지널 효과 3종을 한 번씩 지급한다. 총 12개 효과이며 각 효과의 추가 강화는 0이다. 내부 선택 횟수는 [1,1,1]로, 최대 강화 [3,3,3]과 구별된다. 고귀 퀘스트 보상은 유지한다.
- 일반 아이템 상자를 시작 직후 플레이어 옆 약 2 거리에서 1개 생성하고, 전투 시간 15·30초마다 현재 플레이어의 4~7 거리 안에 1개씩 생성한다. 기존 상자 보상과 상호작용을 재사용하며 장애물·상자와 겹치는 위치를 피한다. 로딩·일시 정지·증강 선택 중에는 생성 시간이 흐르지 않고, 45초 종료 시 추가 생성하지 않는다.
- 제한 시간 생존은 성공, 사망은 실패다. 사망 연출 시간을 생존 시간에 더하지 않는다.
- 한 판에 기존 필드 이벤트 한 종류를 무작위 선정하고 20초에 한 번 실행한다. 20초 이전에 종료되면 발동하지 않는다.
- 상점, 혈전 이동, 추가 보급 선택 등 장기 탐험용 초기 필드 오브젝트는 이 모드에서 배치하지 않는다.

## 시작 구성과 밸런스

`Assets/Junhan/Resources/FestivalDemoSettings.json`에서 제한 시간, 적 등장량, 체력 배율, 개체 수 상한, 고귀 퀘스트 목표, 캐릭터별 시작 구성을 조정한다. 화면과 실제 지급은 동일한 설정을 사용한다. 본 게임의 해금이나 장착 저장값을 수정하지 않는다.

| 캐릭터 | 시작 특수 증강 ID | 유물 ID | 아이템 ID | 고귀 보상 |
|---|---|---|---|---|
| 아시 | WindNeedle, Homing, Pierce, ReturnNeedle | feather | 1, 20 | 봉익윤무 |
| 혁이 | IceNeedle, VibrationNeedle, PressureNeedle, Pierce | firm_shield | 12, 2 | 봉명진혼 |
| 신이 | FireNeedle, Explosion, CorrosionNeedle, HungerNeedle | clear_dew | 12, 8 | 봉황파동 |
| 아리 | AcupunctureFormation, MarkNeedle, BipolarNeedle, FiberNeedle | lightning_beat | 1, 2 | 삼중봉익 |

고귀 퀘스트는 20마리 처치, 대시 4회, 액티브 2회 사용의 세 가지다. 모두 완료하면 각 캐릭터의 고귀 증강을 즉시 지급하며 비전서 열기, 완료 버튼, 추가 보상 선택 화면을 요구하지 않는다. 완료 처리에는 중복 방지가 적용된다. 액티브 재사용 시간은 데모에서 최대 24초로 제한하고, 신이는 불씨 18개를 보유한 상태로 시작한다. 최대 체력을 1로 바꾸는 고귀 증강은 자동 보상에 포함하지 않는다.

시작 적 18마리를 나누어 생성하고 초당 일반 적 생성량은 10→18마리, 체력 배율은 1.25→2.4배, 이동속도 배율은 1.05→1.6배로 증가시킨다. 모든 배율은 해당 적의 기본값 기준이며 캐릭터별 난이도를 숨겨서 변경하지 않는다. 몬스터의 공격 피해는 첫 12초 동안 1배이고 이후 45초에 3배가 되도록 부드럽게 증가한다. 대시 무적·방어막·방어력·피해 감소를 그대로 적용하며 필드 이벤트의 피해량에는 이 배율을 적용하지 않는다. 신이의 행사 보정은 피해 +35%, 공격속도 +20%, 체력 +45다. 동시 적 수는 일반·특수 합산 95마리, 특수 적은 최대 8마리다. 보조 적이 많아지더라도 상한을 넘지 않는다.

| 전투 시간 | 특수 적 배치 |
|---|---|
| 7초 | 저격 1 |
| 13초 | 이동속도 버퍼 1 + 저격 1 |
| 20초 | 방어 버퍼 1 + 저격 1 |
| 27초 | 공격속도 디버퍼 1 + 이동속도 버퍼 1 |
| 34초 | 저격 1 + 방어 버퍼 1 |
| 40초 | 저격 1 + 공격속도 디버퍼 1 |

플레이어로부터 5 이상 떨어진 통행 가능한 위치를 고른다. 저격 몬스터의 기존 조준·고정 경고를 유지한다. 전체 상한에 도달하면 먼 일반 적을 점수 없이 회수하고 특수 적 자리를 확보한다.

설계 목표는 초심자에게 어렵고, 중급자 약 10%, 숙련자 약 70%의 완주다. 전체 10%는 참가자 숙련도 구성에 따라 달라지며, 예를 들어 초심자 60%·중급자 30%·숙련자 10%이고 초심자 완주가 거의 없을 때 약 10%가 된다. 자동 조작 결과를 사람의 성공률로 간주하지 않는다. 행사 첫 참가자 데이터를 보고 설정 파일의 생성량·체력·이동속도를 재조정한다.

실제 플레이 난이도는 테스트 결과와 행사 참가자 체험으로 추가 조정한다. 자동 조작 검증은 기능·성능 점검이며 처음 하는 사람의 성공률을 의미하지 않는다.

## 순위

기존 `RunScore`의 처치 점수를 재사용한다. 행사 기록은 기존 온라인 QA 순위에 전송하지 않는다. 기존 온라인 순위는 기기 계정당 최고점이므로 여러 참가자가 공유하는 한 PC의 행사 기록은 별도 누적 장부에 저장한다.

- 입력: 학과 1~40자, 이름 1~24자.
- 저장: 참가자, 캐릭터, 생존 시간, 성공 여부, 점수, 판 식별자, 기록 시각.
- 점수: 기존 점수 + 생존 초당 10점 + 추가 완주 보너스 9,000점. 기존 성공 점수 1,000점을 합해 완주 보너스는 총 10,000점이다.
- 정렬: 생존 성공 우선 → 점수 → 생존 시간 → 먼저 등록된 기록.
- 저장 직후 리더보드로 이동하며 이번 기록을 1위 위에 별도로 고정한다. 해당 기록은 정식 순위에도 남는다.
- 상위 3위에 금·은·동 메달을 표시한다. 전체 기록을 휠·드래그·스크롤바로 확인하며 참가자 수와 기록 수를 따로 표시한다. 참가자 수는 학과+이름 조합 기준이다.
- 성공과 점수는 별도 열을 유지한다. 학과·이름 입력란과 버튼은 스티치 패치 테마다.
- 한 판의 기록 중복 등록을 막고, 다음 참가자 입력값은 비운다.
- 기존 60초 버전 기록도 삭제하지 않는다. 신규 기록의 규칙 식별자는 `festival_pc_v2_45`이며 이전 기록은 `festival_pc_v1`로 남는다. 서로 다른 규칙의 기록이 같은 보드에 보존되므로 행사 공식 순위 초기화가 필요하면 장부를 먼저 백업하고 별도로 진행한다.
- 저장 위치: Unity `Application.persistentDataPath` 아래 `Festival/leaderboard-v1.json`.
- 저장은 임시 파일 작성 후 교체하며 직전 정상 파일을 `.bak`으로 보관한다. 저장 실패 시 입력값을 유지한다.
- 네트워크 연결은 필요하지 않는다. 여러 PC 사이의 순위 통합은 이번 구현에 포함하지 않는다.

## 행사 최소 QA (2026-10-27)

요청에 따라 캐릭터 선택, 평균 FPS, 심한 끊김, 오류만 별도로 수집한다. 기존 리더보드 정보는 QA와 합치지 않는다.

- 선택은 버튼 클릭이 아니라 실제 출전 기준이다. 순위 미등록 플레이도 포함하며 재도전은 별도 출전이다. 같은 판의 체크포인트는 선택 수를 증가시키지 않는다.
- FPS는 활성 전투의 총 프레임/실제 측정 시간이다. 로딩·일시정지·비활성 창·메뉴·사망 후 연출을 제외하고 재개 직후 이전 구간을 연결하지 않는다. 캐릭터별 평균도 합계 프레임/합계 시간으로 가중 계산한다.
- 100ms 이상 프레임 수, 250ms 이상 프레임 수, 최장 프레임을 기록한다. 250ms는 100ms에도 포함되며 연속 지연 프레임은 각각 센다.
- 출전 시 즉시 저장, 5초마다 교체 저장, 정상 종료·창 비활성 시 체크포인트. 임시 파일 작성 후 교체하며 직전 파일은 `.bak`으로 복구한다. 강제 종료는 마지막 체크포인트까지만 남을 수 있다.
- Unity Error/Exception/Assert만 수집하며 메시지·인자·파일 경로를 버리고 종류와 호출 함수만 저장한다. 오류 폭주 시 큐/세부 그룹은 각 256개로 제한하고 넘친 개수는 별도 합산한다. 경고 로그와 OS 하드 크래시 덤프는 수집하지 않는다.
- 이름·학과·점수·체력·처치·스킬 사용량·키 입력·PC 계정명·하드웨어 식별자는 QA에 포함하지 않는다. PC 구분은 무작위 코드이며 버전/출전/측정 시간 등 해석에 필요한 메타데이터만 함께 남긴다. 네트워크 전송은 없다.
- 선택 화면 오른쪽 위 `QA 데이터` → `QA 내보내기` → 바탕화면 `FestivalQA_exports`의 최신 ZIP. UTF-8 BOM CSV 3종, 정규화 원본 JSON, 읽기 안내를 포함한다. `저장 폴더 열기` 지원. 원본은 유지한다.
- 저장: `Application.persistentDataPath/Festival/QA`. 에디터는 `Library/FestivalQaTelemetry`에 격리한다. ZIP 간 PC번호+출전번호/오류 세션으로 중복을 제거할 수 있다.
- 검증: `Vampire.Tests.Editor.FestivalDemoSmoke.RunQa` (1000건 저장·복구·ZIP·CSV, 임계값/평균 계산, 오류 익명화/폭주, 실제 출전·UI 연결). 빌드까지는 `RunQaAndBuild`.

## PC 성능 범위

기존 적·투사체 풀과 이벤트를 재사용한다. 적의 동시 활성 개체 수는 95마리, 한 프레임당 생성량은 6마리로 제한하고, 프레임 지연 이후 밀린 적 생성이 한 번에 몰리지 않게 한다. 화면 밖 멀리 남은 일반 적은 0.5초마다 최대 12마리씩 풀로 회수해 새 적의 등장 여유를 확보하며, 이 회수에는 처치 점수를 지급하지 않는다. 일반 플레이의 킬별 영구 실버 저장과 치명타별 디버그 로그를 데모에서는 수행하지 않아 전투 중 저장 부하를 줄인다.

## 검증과 빌드

- 통합 검증: Unity 2022.3.62f3에서 `Vampire.Tests.Editor.FestivalDemoSmoke.Run`.
- 검증 결과: `Library/FestivalQA/`의 결과, 전투 측정 CSV, 화면 캡처.
- PC 빌드: 메뉴 `24투/Build festival demo for Windows PC` 또는 `Vampire.Editor.FestivalDemoBuild.Run`.
- 기본 빌드 폴더: `Builds/FestivalDemoPC`. `PROJECT_GC_WINDOWS_OUTPUT`으로 별도 출력 폴더를 지정할 수 있다.
- 페스티벌 빌드는 반복 제작 시간을 줄이기 위해 빠른 LZ4 압축을 사용한다. 일반 빌드의 LZ4HC 설정은 유지한다.
- 실행 파일과 데이터 폴더를 함께 배포한다. 실행 파일만 복사하면 안 된다.
- `Tools/Distribution/UpdateFestivalInstall.ps1 -BuildFolder <검증한 빌드> -InstallFolder <설치 폴더>`는 파일 확인 후 기존 실행판을 별도 백업하고 교체한다. 기존 바탕화면 바로가기의 경로와 LocalLow 참가 기록은 유지한다.
- 간단 실행 안내는 `Documentation/FestivalDemo-QuickStart.txt`에서 빌드의 `실행안내.txt`로 복사한다.

`FestivalDemoSettings.json`의 `enabled`를 끄면 기존 흐름을 사용할 수 있다. 본 게임에 병합하는 작업은 이 데모 작업에 포함하지 않는다.

## 2026-10-27 게이지 안내와 캐릭터 조정

- 매 판 로딩 완료 직후 실제 PlayerCombatBars의 세 Rect를 강조한다. 73% 검정 배경에 해당 영역만 뚫고 안내선을 연결한다. 스티치 패널을 사용한다.
- 안내 중 Time.timeScale=0: 적 이동·공격·타이머·쿨타임과 QA 성능 측정을 멈춘다. 게임 시간 0초에서 시작한다.
- 아무 곳이나 클릭/터치 또는 Space로 닫는다. 입력 해제와 한 프레임 경계를 기다려 시작 입력의 액티브 발동/불씨 소모를 차단한다.
- 참가자가 바뀌므로 저장된 최초 실행 플래그를 사용하지 않고 매 판 표시한다.
- 신이는 노란 게이지를 불씨 연료로 설명한다. 나머지는 액티브 쿨타임이다.
- 아리와 혁이: 기존 페스티벌 24초 상한 적용 뒤 각각 0.6 배율. 시작 쿨타임 14.4초.
- 신이: 액티브에만 1.8 피해 배율. 기존 불씨·발사 시간·기본 침 공격은 그대로. 강화 전 35 DPS → 63 DPS이며 캐릭터/아이템 배율은 추가 적용.
- 이 수치는 페스티벌 모드에만 적용한다. 설정은 Resources/FestivalDemoSettings.json의 세 active 배율 필드.
